# NICKS — реестр ников чатов (см. CHARTER §12)

Одну «роль» (`A`/`B`/`C`/`D`/`L`/`ORCH`) во времени может обслуживать НЕСКОЛЬКО физических чатов
(новый запуск, `--resume`, восстановление после краха). Ник — короткая замена длинного chat id
в повседневном обиходе (`sessions/<ID>.md`, `ACTIVITY.md`, `HANDOFFS.md`). Формат ника: `<Роль><n>`,
`n` — следующий свободный номер для этой роли, в порядке РЕАЛЬНОГО времени создания чата (не
последней активности). Регистрируй здесь ПЕРЕД тем, как занять лок (CHARTER §12) под новым ником.

## Правила ведения

1. Новый физический чат под ролью `<ID>` перед тем, как занять лок в `sessions/<ID>.md`:
   - смотрит последнюю строку с этой ролью здесь → берёт следующий номер (`<ID><n+1>`);
   - если знает свой chat id (например, дан во входной команде `claude --resume <uuid>`) —
     вписывает; если нет — пишет «не зафиксирован» (не блокирует регистрацию).
   - добавляет строку сюда со статусом `active`.
2. Когда чат останавливается штатно (переводит лок в `FREE`) — меняет свой статус здесь на
   `retired`, НЕ удаляя строку (история ников — не переписывается, только append/пометка).
3. Ники одной роли **никогда не переиспользуются** — новый чат всегда берёт следующий номер,
   даже если предыдущий ник давно `retired`.
4. Эта таблица — процедурный реестр, не техническая база данных: ведение вручную, добросовестно,
   каждым чатом за себя. Чужие строки не редактировать (кроме ORCH при разборе конфликта).
