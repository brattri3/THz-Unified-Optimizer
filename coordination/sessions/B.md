## Состояние зоны (что сделано и чем это проверяется)

`research/experiments/model_core.py` — векторизованное по частоте + кэширующее ядро Бланко.
Кэш `t_perp`/`t_par` по ключу `(ν-сетка, P, D, N, use_drude)`; ключ — точные биты float
(округление склеило бы соседние `D` численного якобиана lmfit и испортило производную).

Схлопнуто: **3 копии грида** (`compute_theoretical_grid_2d` / `compute_grid_hn2` /
`compute_grid_hn8`) и **5 копий невязки** → одна пара `compute_grid` + `complex_residual`.
Переведены `t6_hn2`, `t6_hn8`, `model_m5`, `t20_weighted_fit`, `fit_lib`; `t8`, `t6_hn6`,
`t9`–`t19` получили ускорение транзитивно. Имена `tN_` и публичные функции сохранены
как тонкие алиасы — внешние вызовы не сломаны.

**Численный контракт — побитовый, не «в пределах допуска».** Две ловушки ULP, без которых
равенства не получить (описаны в комментариях, НЕ упрощать):
- `_cpython_cdiv` — CPython делит комплексные иначе, чем NumPy (затрагивает
  `get_drude_impedance_normalized`, считающий на Python-complex);
- `_cmul` / `_csq` — ufunc комплексного умножения NumPy сворачивается в FMA для массивов,
  но не для скаляров (расхождение на ~45% случайных пар).

Проверяется:
```powershell
.venv\Scripts\python.exe research\experiments\verify_model_core.py            # ALL CHECKS EXACT
.venv\Scripts\python.exe research\experiments\refactor_ab_check.py --diff pre post3
.venv\Scripts\python.exe research\experiments\refactor_ab_check.py --diff pre_fitlib post_fitlib
```
Результат: 47 AIC и 1025 числовых полей — 0 расхождений. Ускорение: вызов грида
27–45 мс → 0.5 мс (0.04 мс на кэш-хите); наборы фитов 15.3× и 7.3×.
