# coordination/ — что здесь лежит и что из этого читать

Каталог плоско держал 16 документов, среди которых перемешаны действующие правила, разовые
отчёты, черновики и данные инструментов. Новой роли было неочевидно, что открывать
(`reports/REPO_AUDIT_2026-08-08.md` §5). Этот файл — карта. **Держать коротким.**

## Читать при холодном старте — три файла, в этом порядке

| # | Файл | Зачем |
|---|---|---|
| 1 | **`PROJECT.md`** | Кто есть кто: роли, зоны, как начать. Входной документ |
| 2 | **`BOARD.md`** | Что открыто прямо сейчас — **только свою строку**. Регламент: ≤ ~10 строк на роль |
| 3 | **`CHARTER.md`** | Механика: формат коммитов, `.lock` (§12), конфликты (§8), роль ORCH (§9), журнал запусков работников (§13), объём BOARD (§14) |

Всё остальное открывается **по поводу**, а не при старте.

## По поводу

| Файл | Когда открывать |
|---|---|
| `OWNERSHIP.md` | «Можно ли мне править этот путь?» Полная карта владения, включая раздел «Остальное дерево» |
| `QUESTIONS.md` | Нужно решение владельца — или надо узнать уже принятое. **Единственное место**, где роль видит решение, не имея доступа к чужому чату |
| `HANDOFFS.md` | Передача между ролями; запуск фонового работника (обязательная запись, CHARTER §13) |
| `ACTIVITY.md` | Append-only журнал, 320 КБ. **В холодный старт не входит.** Читать точечно, когда нужна предыстория решения |
| `LAUNCH_PROMPTS.md` | Запускаешь новую сессию — готовые промты |

## Только для ORCH

| Файл | Что это |
|---|---|
| `orch/`… (пока в корне: `ORCHESTRATOR.md`, `ORCH_BRIEF.md`) | `ORCHESTRATOR.md` — обязанности контролёра каждый проход; `ORCH_BRIEF.md` — шесть целей проекта и решения ORCH. Прочим ролям не нужны |
| `sessions/` | Журналы намерений ролей: что делаю, какие файлы трогаю. ⚠ Блок «🔒 Замок исполнения» в шапке — наследие отменённого механизма, ничего не значит; следующий чат роли удаляет его из своего файла |

## Не действующее, но и не мусор

| Файл | Статус |
|---|---|

Там код отменённого механизма `.lock` и закрытый реестр чатов; разбор — README того каталога. В `coordination/` их больше нет; ссылки в append-only истории читать со сдвигом пути |

| `TEMPLATE_MAP.md`, `TEMPLATE_BACKLOG.md` | Заготовки на будущее извлечение протокола в переносимый шаблон. При обычной работе не нужны |
| `reports/` | Разовые отчёты с датой в имени: аудит структуры, отчёт о миграции, разбор отладки протокола, KPI |
| `handoffs/` | Архив промтов/отчётов ORCH по заходам |

## Правило

Новый файл в корне `coordination/` — только если его читают **все** роли. Разовый отчёт → в
`reports/` с датой в имени. Промт или отчёт по заходу → в `handoffs/`. Иначе каталог снова
зарастёт, и следующей роли опять будет непонятно, что открывать.
