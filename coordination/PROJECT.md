# PROJECT — роли, зоны, протокол вопросов

> **Не входит в холодный старт.** Точка входа роли — `coordination/roles/<ID>.md`.
> Здесь — канонная таблица «кто есть кто» на случай, когда нужна картина целиком:
> спор о зоне, запуск новой роли, передача работы.
>
> Полная карта путей — `OWNERSHIP.md`. Как складывались границы — `rationale/ZONES_HISTORY.md`.

## Роли и зоны

| Роль | Имя сессии | Специализация | Пишет |
|---|---|---|---|
| **A** | `a-model` | прямая модель, идентифицируемость, проверка гипотез | `research/two_wgp/**`, `research/results/two_wgp/**`, `research/hypotheses/**`, скрипты-гипотезы `research/experiments/tN_*.py` |
| **B** | `b-core` | техническая гигиена: рефакторинг, дубли, инварианты, работоспособность + численное ядро | `model_core.py`, `fit_lib.py`, `verify_*`, `scripts/**`; `unified_optimizer/**` — по разовой санкции владельца |
| **C** | `c-app` | приложения-прототипы | `attenuator_app/**`, `track_viewer/**`, `docs/attenuator_app/**`, `docs/track_viewer/**` |
| **D** | `d-paper` | статья для рецензента + образовательный курс | `research/paper/**` |
| **L** | `l-lit` | литература, метапоиск, обзор поля | `research/literature/**` |
| **P** | `p-report` | отчётные презентации для владельца | `research/presentations/**` |
| **ORCH** | `orch` | координация, мержи, регламент | `coordination/**`, `CLAUDE.md`, `archive/**`, main `research/state.json` |

**Схема имён — `<буква роли>-<роль в проекте>`** (решение владельца 2026-08-09). Буква впереди,
чтобы `claude agents` сортировал список по ролям и чтобы связь с префиксом коммита читалась в
имени. Буквы `A`…`P` — идентификаторы протокола, они не переименовываются.

## Две границы, которые чаще всего путают

**B ↔ A — по слою, а не по каталогу.** B владеет численным ядром (`model_core`, `fit_lib`,
`verify_*`) и ролью ревьюера эквивалентности; A владеет скриптами-экспериментами и гипотезами
поверх ядра и пишет их **без** хэндоффа к B. Инвариант: второй копии Бланко, грида, невязки или
билдера не заводить — звать `model_core`; форк только через хэндофф с обоснованием.

**D ↔ L — по жанру.** L пишет **обзор поля**: находит источники, держит выжимки и corpus, отвечает
«что говорит литература». D пишет **обзор для статьи**: отбирает, интерпретирует, позиционирует
новизну. Первичный поиск D не ведёт — запрос `ОТ D К L` в `HANDOFFS.md`.

## Протокол вопросов (`QUESTIONS.md`)

Уперся в решение, которое не твоё, — не решай сам и не замалчивай: строка в `QUESTIONS.md`.

- **`blocking`** — шаг невозможен вообще. Остановись, изменений не делай, жди ответа.
- **`non-blocking`** — есть разумное умолчание. Прими его, **запиши в ту же строку, какое и
  почему**, продолжай работу.
- Закрывает строку владелец или ORCH (`статус → resolved`, ответ дописывается).
- Файл **append-only**: текст уже заданного вопроса и уже принятого решения не переписывается под
  новую реальность — иначе журнал решений перестаёт быть свидетельством.

## Две машины

Проект живёт на рабочем ПК и на ноутбуке. `claude agents` видит сессии только на текущей машине;
согласование между машинами держится на git — подтянуть перед работой, отправить после разрешения
владельца. Механизма, который видел бы обе, нет ни штатного, ни самодельного.

Проверяй существование пути перед обращением: отсутствие соседнего каталога — это другая машина,
а не сбой. Микрофото (`.bmp`) есть только на рабочем ПК.
