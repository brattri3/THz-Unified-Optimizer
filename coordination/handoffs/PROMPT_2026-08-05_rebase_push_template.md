# Промт для ORCH (O6) — ребейз, пуш песочницы, подготовка к шаблону

## Решения владельца

По итогам опросника:

- **`origin/main` не трогаем.** Пушим только `sandbox/scheduling-dev` — после ребейза она будет
  содержать и семь коммитов `main`, и три своих, то есть один пуш резервирует всю работу за два дня.
- **Долларовые пороги SEC отменяются.** Владелец тратит не деньги, а 5-часовое и недельное окно
  лимитов. Мерить надо `/usage` (две цифры: окно и неделя), а не оценку по таблице тарифов.
  `SCHEDULING.md` в этот заход **не правим** — фиксирую, чтобы ты не тратил силы на §8 п.3.
- **`--touch` для `.lock` делаем, но следующим заходом.** Продление необязательное, таймаут
  остаётся 15 минут — до первых реальных автономных тестов. Сейчас режим ручной, сессия одна,
  забирать роль некому.
- **Извлечение в шаблон — «средний путь»:** репозиторий владелец заведёт сам, файлы туда пока не
  копируем, но дешёвую подготовку начинаем сегодня (Задачи 4–5 ниже).

**Границы:** не трогать `SCHEDULING.md`, `research/**`, не делать `--touch`, не начинать Фазу C.

**Про лимиты:** заход длинный. Задачи 0–2 обязательны, 3–5 желательны, 6 — по остатку. Упрёшься в
лимит — останови на границе задачи, напиши где остановился, не бросай на середине ребейза.

## Задача 0 — закоммитить хвосты ДО ребейза

`git status` в конце прошлого отчёта показывает незакоммиченные `coordination/ACTIVITY.md` и
`coordination/NICKS.md`. **Ребейз на грязном дереве не начинать.** Оба изменения законные

## Задача 1 — ребейз `sandbox/scheduling-dev` на `main`

Ветка никогда не пушилась, ребейз безопасен и даёт линейную историю. Считаешь мерж уместнее —
сделай мерж и объясни почему.

**Правила разрешения конфликтов:**

- **`NICKS.md` — конфликт гарантирован, и это новое по сравнению с прошлым промтом.** В `main`
  таблица теперь содержит O3 и O6 (Задача 0), в песочнице — O3, O4, O5. Слить в один список
  **O3 → O4 → O5 → O6**, ни одной строки не терять, порядок по номеру ника. Раздел «Правила
  ведения» берётся из `main` (он там переписан заходами f317af7/efe485b), песочница его не трогала.
- **`ACTIVITY.md`** — append-only: обе стороны сохранить, упорядочить по дате/времени, ничего не
  удалять и не править по смыслу.
- **`BOARD.md`, строка ORCH** — за основу версию `main` (она знает про O6 и правки §12/§5),
  дописать в неё содержательное из песочницы (Фаза B, состояние `SCHEDULING.md`).
- **`sessions/ORCH.md`** — держатель и heartbeat по ФАКТУ (сверься с реальным `.lock`), не «чья
  сторона новее по коммиту».
- **`CHARTER.md`, `.gitignore`, `SCHEDULING.md`** — конфликта быть не должно (разные стороны их не
  пересекали). Если он всё же возник — остановись и опиши, не разрешай наугад.
- Любой конфликт, не сводящийся к этим правилам — остановись и опиши.

**После ребейза — проверка ссылок на сдвинутые хеши.** Ребейз только что переписал
`46761ee`/`1b89a1d`/`68790c5`. Найди все упоминания этих (и любых других) хешей в
`SCHEDULING.md`, `ACTIVITY.md`, `BOARD.md`, `NICKS.md` и **перечисли в отчёте**. Правь **только**
те, что в координационных файлах и очевидно мертвы — по конвенции §5 (дата + файл вместо хеша).
Упоминания внутри `SCHEDULING.md` **не трогай**: его содержимое ещё не подтверждено владельцем.

**Проверка после:** `preflight.py ORCH` (read-only inspect). Ожидаемо покажет «ПРОСРОЧЕНО» — это
известный дефект (таймстамп `.lock` не обновляется), а не признак проблемы. Реклейм не делать,
`--acquire` повторно не вызывать. `stress_test_lock.py` не нужен, кода никто не трогал.

## Задача 3 — папка для промтов и отчётов

Владелец не хочет копить мусор в корне. Завести **`coordination/handoffs/`**, перенести туда
существующие `PROMPT_*.md` / `REPORT_*.md` / `commits_review_*.txt` из корня, закоммитить как

вывод. Если подпадает — поправь.

## Задача 4 — завести `coordination/TEMPLATE_BACKLOG.md`

Дорожная карта извлечения говорила заводить его в тот момент, когда впервые появится что положить.
Появилось. Формат — как в дорожной карте (append-only, одна запись = одна находка, статус
`open`/`resolved`, категория `generic-bug` / `needs-parametrization` / `design-question`).

Две записи, обе `open`, обе `generic-bug`:

1. **Таймстамп `.lock` никогда не обновляется.** §12 п.2 прямо запрещает трогать `.lock` после
   занятия, heartbeat живёт только в человекочитаемом блоке `sessions/<ID>.md`, который
   `preflight.py` по конструкции не читает. Следствие: любая сессия дольше таймаута выглядит
   просроченной, и конкурент получает код `1` (реклейм разрешён) вместо `2` (занято). Вскрыто
   `preflight.py ORCH` inspect по живой сессии O6, 2026-08-05. При извлечении: чинить и в шаблоне;
   планируемое решение — операция продления (`--touch`) плюс сценарий в `stress_test_lock.py`.
2. **Двойной `--resume` одной сессии смешивает транскрипты.** По документации Claude Code, если
   возобновить одну сессию в двух терминалах без ветвления, сообщения обоих смешиваются в один
   файл. Для модели «один ник — одна беседа» это отдельный способ сломать учёт, и в `NICKS.md`
   про него ничего не сказано. При извлечении: либо правило в шаблоне, либо явное ограничение.

Формулировки пиши свои, содержание — выше. Ничего не «чинить» по этим записям в этом заходе.

## Задача 5 — карта переносимости вместо разметки в тексте

Дорожная карта предлагала построчные маркеры `<!-- GENERIC -->` / `<!-- THZ-SPECIFIC -->` прямо в
`CHARTER.md`/`OWNERSHIP.md`. **Предлагаю от этого отказаться, и вот почему:** после правки §7
`CHARTER.md` читается целиком при каждом холодном старте, то есть каждый маркер — постоянный
расход контекста у всех будущих сессий. Ровно та статья расходов, которую §7 и сокращал.

Вместо этого — отдельный **`coordination/TEMPLATE_MAP.md`**: таблица «раздел → generic /
thz-specific / смешанный», на уровне разделов (§), не строк. Стоит ноль при холодном старте,
а при извлечении даёт то же самое.

Честный минус, назови его в самом файле: карта может разойтись с документом, а построчный маркер
разойтись не может. Гранулярность по разделам этот риск ограничивает, но не убирает.

Заполнить по тому, что реально знаешь на сегодня — `CHARTER` (§5, §7, §12 — механика; §9 роли
A/B/C/D/L — специфика), `NICKS.md` (правила ведения vs таблица), `coordination/tools/**`,
`OWNERSHIP.md`. Не угадывать про то, чего не смотрел — помечай `?`.
