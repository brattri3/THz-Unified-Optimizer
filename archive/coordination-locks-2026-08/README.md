# coordination-locks-2026-08 — самодельный слой координации сессий как процессов

Заморожено **2026-08-15** решением владельца (`coordination/QUESTIONS.md`, В-27).

## Что здесь лежало и зачем строилось

С 24.07 по 15.08 проект вёл собственный учёт того, **кто из чатов сейчас работает** — потому что
тогда Claude Code этого не показывал. Слой состоял из двух частей:

| Файл | Что делал |
|---|---|
| `tools/preflight.py` | Технический гейт: создавал `coordination/sessions/<ID>.lock` атомарно (`os.O_CREAT\|os.O_EXCL`), возвращал коды 0/1/2/3/4 — свободно / реклейм по таймауту 15 мин / занято / повреждено / ошибка |
| `tools/stress_test_lock.py` | Стресс-тест гейта: 30 параллельных процессов, проверка «ровно один победитель» |
| `tools/kpi_stats.py` | Статистика работы сессий: парсила `NICKS.md` + локальные транскрипты Claude Code + `git log` |
| `tools/kpi_report.py` | HTML-отчёт поверх `kpi_stats.py` |
| `NICKS.md` | Реестр чатов: ник → роль → chat id → период жизни → статус. Закрыт раньше остальных, **2026-08-07** |

Вокруг этого в уставе жили: таймаут простоя 15 минут, процедура `[STALE-LOCK]`, блок
«🔒 Замок исполнения» в каждом `coordination/sessions/<ID>.md`, heartbeat как признак жизни,
эвристика «замок старше ~1 ч = роль брошена», обязанность ORCH снимать устаревшие замки.

Механизм работал и был не бутафорским: атомарность подтверждена стресс-тестом, реальные коллизии
он ловил (в том числе задвоение сессий L1/L2 — случай, ради которого §12 и переписывался 03.08).

## Почему заморожено

Claude Code к версии `2.1.233` даёт то же самое штатно и точнее: `claude -n <имя>` / `/rename` для
опознания, `claude agents --json` — живой список процессов с `name`, `status`, `pid`, `cwd`,
`sessionId`. Четыре довода, по которым слой признан избыточным (полностью — `CHARTER.md` §12):

1. **`.lock` врал после краха.** Файл оставался лежать и утверждал, что роль занята, когда чата уже
   не было. Весь аппарат таймаутов и реклеймов существовал, чтобы чинить враньё собственного файла;
   `claude agents` показывает процесс, а не его след.
2. **Между машинами не работал вовсе.** `.gitignore` исключает `coordination/sessions/*.lock` —
   лок локален для компьютера, а проект живёт на двух (рабочий ПК и ноутбук).
3. **Настоящую защиту файлов даёт git** — конфликт слияния и отказ `--ff-only` нельзя обойти по
   невнимательности; лок защищал лишь от одновременного старта двух чатов одной роли на одной
   машине.
4. **Стоил дороже, чем давал:** ~100 строк устава, четыре файла кода, ритуал на старте и остановке,
   блок в каждом файле роли — и порождал собственные дефекты учёта (реклейм с простоем 5484 минуты;
   ложная запись «роль P без следов работы» при выполненной и лежащей в репозитории работе).

## Что из этого сохранено в действующих правилах

Принцип, ради которого слой и строился, никуда не делся — сменился исполнитель:

> **Координацию сессий как процессов ведёт сам Claude Code. Наш регламент координирует только
> предметную работу — зоны, решения, находки, историю.** (`CHARTER.md` §12)

Практически: имя роли при запуске (`claude -n a-model` и т. д.), один взгляд в
`claude agents --json` перед началом работы, дальше — зоны `OWNERSHIP.md` и разметка коммитов.
Правило «одна зона — один исполнитель» действует по-прежнему, проверяется командой, а не файлом.

## Оговорки для того, кто сюда заглянул

- **`NICKS.md` остаётся достоверным как история.** По нему восстанавливается, какой чат что делал
  с 24.07 по 06.08 (последняя запись — `D3`). Ники после неё (`O7`, `O8`, `A4`, `A5`, `C2`, `P2`)
  туда **намеренно** не заносились: реестр был закрыт 07.08, и незаполненность — исполнение
  решения, а не небрежность.
- **Ссылки на `coordination/NICKS.md` и `coordination/tools/**` в append-only истории
  (`ACTIVITY.md`, `HANDOFFS.md`, `handoffs/**`, `reports/**`) не переписывались** — они верны для
  своего времени. Читать как: путь стал `archive/coordination-locks-2026-08/…`.
- **Код не запускать.** Он работоспособен, и в этом опасность: `preflight.py --acquire` создаст
  `.lock`, на который никто больше не смотрит, и вернёт ложное ощущение защиты.
