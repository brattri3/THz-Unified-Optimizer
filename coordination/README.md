# coordination/ — карта каталога

**При старте роль читает ровно один файл: `roles/<ID>.md`.** Указатель «что читать по какому
поводу», с ценой в токенах, — в `CLAUDE.md`, который грузится сам. Ниже — что здесь лежит.

## Точки входа

| Что | Файл |
|---|---|
| **Вход роли** — зона, что открыто, что дальше | `roles/<ID>.md` |
| Сводка по всем ролям на один экран | `BOARD.md` |
| Таблица ролей и зон целиком, протокол вопросов | `PROJECT.md` |
| Ядро правил: коммиты, зоны, конфликты, стиль | `CHARTER.md` |

## Журналы — пишутся, а не читаются целиком

| Файл | Правило |
|---|---|
| `QUESTIONS.md` | решения владельца, **append-only**: заданный вопрос и принятое решение не переписываются |
| `HANDOFFS.md` | межролевые запросы. ⚠ 46 тыс. токенов — **искать поиском** |
| `ACTIVITY.md` | журнал изменений между сессиями. ⚠ 139 тыс. токенов — **никогда целиком** |
| `sessions/<ID>.md` | намерения роли: что делаю, какие файлы трогаю |

## Справочники

| Файл | Что |
|---|---|
| `OWNERSHIP.md` | полная карта владения путями; правило «нового каталога верхнего уровня без строки не заводить» |
| `LAUNCH_PROMPTS.md` | команды и промты запуска ролей |
| `rationale/` | **почему** приняты решения: отмена локов, журнал фоновых работников, история зон, отменённый регламент объёма доски |
| `reports/` | разовые отчёты с датой: аудиты, замеры, планы, миграции |
| `handoffs/` | архив промтов и отчётов ORCH по заходам |

## Только для ORCH

`ORCHESTRATOR.md` — обязанности контролёра. `ORCH_BRIEF.md` — шесть целей проекта и решения ORCH.
Прочим ролям не нужны.
