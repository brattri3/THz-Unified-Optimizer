# THz Unified Optimizer

Извлечение физических параметров проволочных поляризаторов (WGP) — периода `P` и эффективного
диаметра проволоки `D_eff` — из данных терагерцовой спектроскопии во временной области (THz-TDS).

Ядро — аналитическая модель **Бланко (1986)**: эквивалентные схемы дают коэффициенты пропускания
`t_perp` и `t_par`, дальше формализм матриц Джонса. Поверх модели — поправки: Друде, степенное
рассеяние `ν^γ`, фазовые задержки, утечка параллельного канала.

> Проект исследовательский и незавершённый. Ключевая открытая задача — **загадка `D_eff`**: подгонка
> устойчиво требует `D_eff/D_phys ≈ 0.43–0.64` на трёх образцах, тогда как точный lattice-sum эталон
> даёт отношение ≈ 1. Значит `D_eff` — не геометрический размер, а прокси недостающей физики.
> Разбор — `research/SYNTHESIS.md`.

## Два слоя репозитория

Это главное, что нужно понять до чтения кода: слоя два, и они живут по разным правилам.

| Слой | Где | Состояние |
|---|---|---|
| **Продакшн-пайплайн** | `unified_optimizer/`, `scripts/` | **Заморожен.** Содержит два известных дефекта (ниже). Правится только по разовой санкции владельца: любая правка сдвигает базовую линию всех прошлых подгонок |
| **Исследовательский слой** | `research/` | **Активен.** Всё новое пишется сюда |

Исследование использует продакшн-пакет **как библиотеку** (`model_blanco`, `config`,
`data_manager` и две функции из `optimizer_2d`), а не как приложение.

### Известные дефекты продакшн-кода

1. `unified_optimizer/optimizer_2d.py:122` — обращение к неопределённому имени `p_max_um`
   ⇒ `optimize_2d_spectral()` падает с `NameError`, а с ним и `run_pipeline --method 2d|both`
   (это значение по умолчанию). Регрессия внесена коммитом `b0372ce` 2026-07-19.
2. `unified_optimizer/optimizer_lmfit.py:92` — вызов `model_blanco.…` при отсутствующем импорте
   ⇒ `run_lmfit_2d()` тоже `NameError`.

Функции `optimizer_2d.get_transmission_spectra` и `compute_theoretical_grid_2d` работают — именно
их импортирует `research/`, поэтому исследовательский слой не задет. Починка подготовлена на ветке
`session/B-prod-fix`, в `main` не смержена до проверки.

## Структура

```
unified_optimizer/   продакшн-пакет: модель, оптимизаторы 1D/2D, загрузчик данных, пайплайн
scripts/             скрипты той же эпохи, работают поверх пакета (заморожены вместе с ним)
research/            активный слой:
  experiments/         численное ядро (model_core, fit_lib) и скрипты-эксперименты
  two_wgp/             корректная модель двух реальных WGP
  hypotheses/          проверяемые гипотезы и вердикты
  results/<задача>/    артефакты с числами
  paper/               статья и учебный курс
  literature/          обзор литературы, corpus, извлечённые тексты
  presentations/       отчётные презентации
  validation/          микрофото образцов, ground truth
attenuator_app/      прикладной прототип (расчёт аттенюатора), GUI + сборка exe
data_pool/           экспериментальные данные THz-TDS (только чтение)
coordination/        протокол совместной работы нескольких агентских сессий
archive/             замороженные слои проекта: не исполнять, не пополнять
```

## Запуск

Окружение — Windows, Python 3.14, venv в `.venv`:

```powershell
.venv\Scripts\python.exe -m pip install -r requirements.txt

# продакшн-пайплайн (2D-ветка нерабочая, см. дефекты выше)
.venv\Scripts\python.exe -m unified_optimizer.run_pipeline --method 1d
# отчёт -> results/optimization_report.md  (каталог не трекается в git)

# тесты продакшн-пакета
.venv\Scripts\python.exe -m pytest unified_optimizer/tests -q

# исследовательские скрипты — ВСЕГДА из корня репозитория
.venv\Scripts\python.exe research/experiments/t1_baseline.py
.venv\Scripts\python.exe research/experiments/verify_model_core.py   # бит-в-бит сверка ядра
```

Скрипты в `research/` вычисляют корень репозитория относительно себя, поэтому запуск из другого
рабочего каталога ломает пути к данным.

## Как здесь работают

Над проектом параллельно работают несколько агентских сессий с разделёнными зонами
ответственности (модель и гипотезы, численное ядро, приложение, статья, литература,
презентации + оркестратор). Правила — в `CLAUDE.md`, протокол и карта владения путями — в
`coordination/` (начинать с `coordination/README.md`).

Если вы читаете это как человек и хотите разобраться в физике — самый быстрый путь не код, а
учебный курс в `research/paper/course/` (§0–§10 + приложения).
