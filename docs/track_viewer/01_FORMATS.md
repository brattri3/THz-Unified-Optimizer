# Форматы, отбор файлов и трактовка величин

Справочник по тому, что инструмент считает данными и как именно он их обрабатывает.
Числа здесь — измеренные, а не декларативные: каждое воспроизводится
`python -m track_viewer.selftest`.

## 1. Что считается трассой

Единственное правило отбора:

```
^(\d{3})_(a(-?\d+)|bg|dark)\.txt$
```

| Пример | Что это |
|---|---|
| `003_a0.txt` | трасса образца при угле `0°` |
| `047_a-94.txt` | трасса образца при `−94°` (знак — часть имени) |
| `002_bg.txt` | референс, открытый пучок |
| `001_dark.txt` | перекрытый пучок: непрозрачная преграда на пути излучения |

**Всё, что не совпало, — не трасса, и пропускается молча.** Это не «фильтр мусора», а сам
механизм отсева: одним правилом отсекаются `README.md`, `MEASUREMENT_ORDER.md`,
`000_META_TEMPLATE.txt`, `META.txt`, старые `NNN_META.txt`, подкаталог `microscopy/` — и,
что важнее всего, **нормализованные копии** вида `<набор>_<угол>deg_repN_sig.txt`.

Последних в `test_grid_33_11` 108 штук, и они **побайтно равны** журнальным файлам
(проверено md5). Попади они в выборку — каждая точка угловой зависимости удвоилась бы.

Вид `dark` добавлен 2026-08-13. Файлов с таким именем не было ни в одном
существующем каталоге, поэтому расширение правила архивы не задело; регрессия
проверяется приёмкой явно (`test_grid_33_11` те же 51/17, `purewave` те же 30).
В слайдер и в референсы `dark` не попадает — это не измерение образца.

### Каталоги старой схемы не открываются

`test_grid_40_20` и `specac` состоят **только** из нормализованных имён, журнальной
нумерации в них нет вовсе. Инструмент покажет «сигнальных трасс не найдено» и объяснит,
что именно он ищет. Это не дефект: те наборы сняты до введения журнальной схемы.

## 2. Три состояния файла

| Состояние | Как обрабатывается |
|---|---|
| **нулевой размер** | «ещё не измерено». Пропускается молча; недоснятая дорога считается штатно |
| **разобран** | точка на графике |
| **непустой, не разобрался** | ошибка в панели данных, точки нет, прогон не прерывается |

Пустышки — законное состояние: дорога раскладывается заранее и заполняется по ходу
съёмки. Так же ведёт себя `DataManager` в ядре.

## 3. Содержимое файла трассы

Текст, две или три колонки, разделитель — табуляция, шапки нет:

```
0.000000	-0.094188	570000.000000
0.104167	-0.094404	570200.000000
```

1. время задержки, **пс**;
2. амплитуда поля, отн. ед.;
3. позиция линии задержки — **читается, но в расчётах не участвует** (решение владельца
   O-5, 2026-08-12).

Число точек и длина окна **не зашиты**, а читаются из файла. На эталонных прогонах это
651 точка, шаг 0.104167 пс, окно 67.708 пс, но окно настраивается на приборе.

## 4. Определение повторов

`rep` выводится из порядка: первое появление угла среди сигнальных трасс (по возрастанию
сквозного номера) — `rep1`, второе — `rep2`.

Без этого повторный обход тени из блока 4 плана измерений сливался бы с первым в одну
точку. А разница между ними — это и есть прямая мера дрейфа установки: блоки 3 и 4
`MEASUREMENT_ORDER.md` §2 разделяют физику и дрейф именно так.

## 5. Пропускание во временной области

```
T = ∫ (E_s(t) − DC_s)² dt  /  ∫ (E_r(t) − DC_r)² dt
```

Трапециями по всей трассе. По равенству Парсеваля это тот же интеграл по спектру, поэтому
выбирать границы полосы усреднения не требуется вовсе — у величины нет свободного
параметра, о котором можно спорить постфактум.

### 5.1 Трактовка DC — не деталь

Три режима: `предымпульс` (по умолчанию, среднее по первым 15 % отсчётов) · `полное
среднее` · `нет`. Измерено на `003_a0.txt` / `002_bg.txt`:

| Режим | `T` | в дБ |
|---|---|---|
| нет вычитания | **98.9089 %** | −0.0476 |
| предымпульс 15 % | **99.4231 %** | −0.0251 |
| полное среднее | 99.4273 % | −0.0249 |

Расхождение **+0.514 п.п.** — больше, чем разброс между повторами. Предымпульсный участок
берётся не по всей трассе намеренно: хвост осцилляций смещает полное среднее.

### 5.2 Почему «без DC» — режим сверки, а не рабочий

Режим `нет` существует, чтобы воспроизводить `T_time` из ядра
(`research/two_wgp/a21_transmission_summary.py`). **В зоне гашения он катастрофически
неверен.**

У `011_a90.txt` постоянное смещение детектора `−0.0954` **больше амплитуды импульса**
`0.0765`. Вычитание DC убирает **99.3 %** сырого интеграла у тёмной трассы против 18 % у
яркой, и без него:

| | `T` |
|---|---|
| без вычитания DC | 18.2556 % |
| предымпульс | **0.1511 %** |

Завышение **в 121 раз**. В ярком положении смещение одинаково давит на образец и на
референс, и отношение почти не страдает; в тёмном образец состоит из смещения на 99 %, а
референс — всё те же 18 %.

Инструмент предупреждает сам, когда доля переваливает за 50 %, и молчит в ярком положении.

> **Следствие за пределами инструмента.** `T_time` из `a21_transmission_summary.py`
> считается без вычитания DC и потому пригоден **только для яркого положения**, ради
> которого он там и написан. Переносить его на тёмные углы нельзя.

### 5.3 Расхождение с `a21_transmission.json`

В артефакте для `test_grid_33_11` стоит `T_time = 99.08 %`, а инструмент даёт 98.9089 %.
Причина не в формуле: A21 идёт через `DataManager`, а тот при двух повторах угла
**когерентно усредняет сами трассы** и лишь потом считает `T`
(`unified_optimizer/data_manager.py:84`).

| | `T` |
|---|---|
| rep1 (`003_a0` / `002_bg`) | 98.9089 % |
| rep2 (`068_a0` / `066_bg`) | 98.4612 % |
| среднее по величине `T` | 98.6851 % |
| A21: усреднение полей, затем `T` | 99.08 % |

Инструмент не усредняет повторы вовсе: у прибора каждая трасса — своя точка, и разница
между повторами есть измеряемая величина, а не шум, который надо сгладить.

### 5.4 Пропускание по полосе частот и дельта

Свойство «нет свободных параметров» имеет обратную сторону: в интеграл по времени
попадает **вся** полоса, включая ту её часть, где сигнала уже нет. В ярком положении это
безразлично, в зоне гашения — нет.

Переключатель «считать T по полосе (Парсеваль)» добавляет вторую величину: то же
отношение энергий, но просуммированное только по заданной полосе частот.

```
T_полоса = Σ wₖ|FFT(E_s)|² / ⟨Σ wₖ|FFT(E_r)|²⟩   по полосе счёта
Δ = T_время − T_полоса        Δ_дБ = 10·lg(T_время / T_полоса)
```

Веса `w₀ = 1`, интерьер `= 2`, Найквист `= 1` (только при чётном числе отсчётов) — те
самые, при которых `Σ wₖ|FFTₖ|²/N` равна `Σ Eₙ²` **точно**. Для самого отношения
нормировка сократилась бы, но тогда пропала бы возможность проверить реализацию.

**Полоса счёта отдельна от полосы показа.** Это не дублирование: границы счёта меняют,
не трогая масштаб спектра, — иначе каждое изменение полосы перерисовывало бы график, и
сравнивать было бы не с чем. Полоса счёта показана на спектре заливкой.

Кнопка **«полная полоса — проверка Парсеваля»** ставит `0…Найквист`. После неё `Δ`
обязана схлопнуться. Измерено на `003_a0.txt`:

| | значение |
|---|---|
| `Σ Eₙ²` прямой суммой | 31.880386115622 |
| `Σ wₖ\|FFTₖ\|²/N` | 31.880386115622 |
| расхождение | **0** (побитово) |
| без весов вышло бы | 18.82 — ошибка в 1.69 раза |

Остаточная `Δ ≈ −3.8·10⁻⁶` на полной полосе — это не погрешность Парсеваля, а разница
**способов суммирования**: временной интеграл берётся трапецией, спектральный —
прямоугольной суммой, и вклад дают концы трассы. При включённом окне концы погашены, и
остаток падает до `8·10⁻¹⁰`.

Рабочие числа на `test_grid_33_11`:

| Трасса | полоса | `Δ`, дБ | доля энергии в полосе (образец / референс) |
|---|---|---|---|
| `019_a10`, яркое, T = 92 % | 0.2…3.0 | **−0.002** | 89.9 / 89.8 % |
| `011_a90`, гашение, T = 0.15 % | 0.2…3.0 | **−0.365** | 97.8 / 89.9 % |
| то же | 0.3…1.2 | **−0.863** | 86.1 / 70.6 % |
| то же | 0.4…1.0 | **−1.314** | 67.8 / 50.1 % |

Читается так: в ярком положении вся энергия лежит в полосе, и обе величины совпадают.
В зоне гашения у образца **больше** доля энергии в полосе, чем у референса, — потому что
у тёмной трассы «спектр» вне полосы это шум, а у референса там ещё есть сигнал. Чем у́же
полоса, тем больше расхождение: `|Δ|` растёт монотонно, и приёмка проверяет именно
монотонность, а не совпадение с одним числом.

### 5.5 Учёт окна во временно́м интеграле

По умолчанию `T` во времени **не учитывает** гауссово окно: окно применяется только
перед БПФ. При включённом окне это делает сравнение «время против частоты»
несимметричным по построению — слева трасса не взвешена, справа взвешена, и `Δ`
набирается не только за счёт полосы.

Галочка «учитывать окно во временно́м T» переводит интеграл на ту же подготовленную
трассу, что уходит в БПФ. Измерено на `011_a90.txt` при FWHM 20 пс:
`0.15114 % → 0.14574 %`, то есть **−0.158 дБ**. Режим виден в панели данных, потому что
меняет главное число на угловом графике.

При выключенном окне галочка не влияет ни на что (проверено до `1e-15`).

## 6. Спектральное пропускание

```
T(ν) = |FFT(E_s)|² / |FFT(E_r)|²
```

Полоса по умолчанию 0.2…3.0 ТГц, настраивается. Точки, где спектр референса ниже порога
динамического диапазона (40 дБ по амплитуде от максимума), не отображаются.

**Шумовой пол** рисуется серым пунктиром. Выше него кривая — измерение, на нём — шум,
делённый на сигнал референса. Без этой линии «структура» спектра выше 1.6 ТГц читается
как физика, хотя это шум.

### 6.1 Три источника шумового пола

| Источник | Как считает | Когда брать |
|---|---|---|
| **ВЧ-хвост (Нафтали)** — по умолчанию | среднее `\|FFT\|²` выше `3.0 ТГц` | всегда, если нет причин иначе |
| предымпульс | дисперсия предымпульсного участка × N | сверка с прежними числами |
| перекрытый пучок (`dark`) | среднее `\|FFT\|²` трассы `NNN_dark.txt` | когда `dark` снят |

Метод по высокочастотному хвосту — стандартный, из Mira Naftaly, *Terahertz Metrology*:
выше некоторой частоты спектр перестаёт спадать и выходит на полку, и эта полка есть шум
измерения. На наших прогонах полка начинается около **3.0 ТГц**, где `⟨P⟩ = 1…3·10⁻⁴` и
дальше не падает.

> ⚠ **Прежнее умолчание (предымпульс) завышало пол, и это измерено.** На `002_bg.txt`
> предымпульсная оценка даёт `3.94·10⁻³` против `2.25·10⁻⁴` по ВЧ-хвосту — линия была
> нарисована на **12.4 дБ выше** реального шума. Причина: предымпульсный участок
> содержит не только белый шум, но и низкочастотный дрейф базовой линии. Оператор при
> этом видел завышенный порог и мог счесть измеримую часть спектра шумом.

Метод по ВЧ-хвосту честнее ещё и тем, что оценивает шум **там же, где он мешает** — в
частотной области, — и не подмешивает дрейф.

### 6.2 Перекрытый пучок (`dark`)

Файл `NNN_dark.txt` снимается с непрозрачной преградой на пути излучения. Это прямое
измерение шума закрытого тракта: способ определить динамический диапазон, не опираясь на
предположение о том, где кончается сигнал.

> **Из трасс `dark` не вычитается ни при каких настройках.** Шум некогерентен: вычитание
> его из поля не убрало бы шум, а добавило бы второй независимый экземпляр. Трасса
> перекрытого пучка используется **только** как оценка уровня.

Материал преграды записывается в `META.txt`: металл отражает излучение обратно в тракт,
поглотитель — нет, и уровни выйдут разными.

Если выбран источник `dark`, а таких файлов в каталоге нет, инструмент откатывается на
ВЧ-хвост **с пометкой в панели**. Молча подменённый источник выглядел бы на графике как
штатный результат.

При двух и более `dark` (штатный режим — в начале и в конце прогона) панель
предупреждает, если они расходятся больше чем на **3 дБ**: шум изменился за время съёмки,
и оценка динамического диапазона по одной из них неверна. Порог в 3 дБ — это двукратное
изменение мощности; меньший разброс укладывается в собственную статистику оценки.

## 6.3 Линеаризованный фит закона Малюса

Запрет ТЗ §9 на подгонку модели снят владельцем 2026-08-13. Метод — сессии A,
задача `A0_malus_linearization`; полный вывод — `research/two_wgp/NOTE_malus_linearization.md`.

### Почему подгонка линейная — и почему это не упрощение

Наблюдаемая нелинейна по **углу**, но линейна по **коэффициентам**, если разложить её
по гармоникам угла. Ключевой шаг — школьное тождество `cos²α = ½(1 + cos2α)`:
неизвестный угловой офсет `θ₀` сидел внутри косинуса, что делало задачу нелинейной,
а после разложения вышел наружу и распределился между линейными коэффициентами.

Дальше существенно, что наша схема складывает **поля** и лишь потом берёт квадрат
(`E = t⊥cos²θ + t∥sin²θ`, `U = |E|²`). Поле линейно по `cos2θ`, значит `U` — квадрат
линейной величины, то есть тригонометрический многочлен **ровно 4-го порядка**:

```
U(θ) = c₀ + a₂cos2θ + b₂sin2θ + a₄cos4θ + b₄sin4θ
```

Это **тождество, а не приближение**. Проверяется приёмкой: на синтетике невязка
`1.41·10⁻¹⁶` — машинный нуль.

### Замкнутые формулы

```
|t⊥|²              = c₀ + c₂ + c₄          c₂ = hypot(a₂,b₂)
|t∥|²              = c₀ − c₂ + c₄          c₄ = ПРОЕКЦИЯ на систему офсета,
Re(t⊥·conj(t∥))    = c₀ − 3c₄                  а не hypot: у неё есть знак
θ₀ = ½·atan2(b₂,a₂)      и независимо      θ₀ = ¼·atan2(b₄,a₄)  (mod 45°)
```

Ни итераций, ни стартовой точки, ни мультистарта, ни бутстрапа: минимум один и он
глобальный, ковариация `(XᵀWX)⁻¹` точна. Стоимость — **33 мкс на трек** против 16 мс
на сам пересчёт трека, поэтому фит считается на каждое обновление.

### Порядок 4 обязателен

Учебная 3-параметрическая форма `a₀ + a₁cos2θ + b₁sin2θ` верна для *интенсивностной*
(некогерентной) композиции и для нашей установки систематически неверна. Она
выбрасывает четверть сигнала и **полностью слепа к фазе утечки**: фаза входит только
через 4-ю гармонику.

Идеальный поляризатор даёт `cos⁴θ = 3/8 + ½cos2θ + ⅛cos4θ`, то есть `A₄/A₂ = 0.25`
ровно. Измерено на `test_grid_33_11`: **0.2509**. Четвёртая гармоника присутствует
именно в той пропорции, которую предсказывает когерентная модель.

| Порядок | экстинкция | `η` | `θ₀` |
|---|---|---|---|
| **4 (рабочий)** | **28.20 дБ** | **0.0389** | −1.2822° |
| 2 (учебный) | 17.06 дБ | 0.1403 | −1.1482° |

### Частотная зависимость модели НЕ требует

Возражение очевидное: `t⊥` и `t∥` частотно зависимы, откуда же взяться одной кривой
`T(θ)`. Ответ: на каждой частоте `U(ν,θ)` — многочлен 4-го порядка, а **сумма таких
многочленов снова многочлен того же порядка**. Поэтому `T(θ)` фитируется при любом
поведении `t⊥(ν)`, и никакой модели этого поведения не нужно.

Проверено как тождество, а не как правдоподобие: коэффициенты широкополосного фита
совпали со спектрально-взвешенным средним 190 побинных фитов до **4.7·10⁻¹³**
(при общем векторе угловых весов совпадение точное по линейности МНК).

Следствие для трактовки: широкополосный фит даёт **`⟨|t⊥|²⟩` со спектральным весом
мощности референса**, а не значение на какой-то частоте. Сами спектры `|t⊥|²(ν)` и
`|t∥|²(ν)` даёт побинный фит — тоже без модели, бины независимы.

### Веса решают, слышна ли тень

Невзвешенный МНК по мощности взвешивает точку как `U²`, поэтому яркая зона заглушает
тень — а вся информация об утечке сидит именно в тени. У сессии A такая подгонка на
`series1` дала **`|t∥|² < 0`**, физически невозможное. Рабочий режим — постоянная
*относительная* ошибка `σᵢ ∝ Uᵢ`; задача остаётся линейной, веса не зависят от
подбираемых параметров.

| Веса | `η` | `θ₀` |
|---|---|---|
| относительные (рабочие) | 0.03889 | −1.2822° |
| по шумовому полу | 0.03702 | −1.4653° |
| равные | 0.03626 | −1.4635° |

### Что фит НЕ даёт и почему

Угловой скан на одной частоте способен ограничить **не более пяти вещественных чисел** —
столько их в базисе. Любая модель, вводящая на фиксированной частоте больше независимых
параметров, структурно неидентифицируема из углового скана, сколько бы углов ни снять.
Отсюда и отсутствие геометрии (`P`, `D_eff`) и материальных параметров: это предел
информации, а не недоделка инструмента. Тот же счёт формально объясняет известное
вырождение `D_eff ↔ η` — они конкурируют за одни и те же `c₀, c₂, c₄`.

Что́ выдаётся — это пропускание **всего тракта** относительно открытого пучка, а не
одного элемента, и `η` — **полная** утечка. По результату A3 воспроизводима именно она,
а не её разложение на `D_eff`, `η₀` и `ε_cross`.

### Что ломает линейность

| Ломает | Механизм |
|---|---|
| работа в дБ | `ln` от многочлена — не многочлен, rms 1.73 дБ ⇒ фитуем `U`, логарифм только для показа |
| многолучевая интерференция (Фабри–Перо) | рациональная функция от `cos2θ` ⇒ бесконечный ряд гармоник |
| нелинейность детектора | измеряется `f(U)`, а не `U` |
| погрешность самого угла | МНК считает `θ` точным; люфт столика даёт смещение и не лечится подгонкой |
| неполный угловой диапазон | базисные функции перестают быть ортогональными |

**Не ломают:** частотная зависимость `η(ν)`, фазовый член, суммирование по Парсевалю,
двух-WGP структура, рассогласование второго поляризатора, нормировка на референс.

### Три бесплатных проверки, которых нет у нелинейного фита

1. **Два независимых `θ₀`** — из 2-й и из 4-й гармоник — обязаны совпасть. На
   `test_grid_33_11` расхождение **0.0053°**. Больше 0.1° = систематика по углу.
2. **Неравенство Коши–Буняковского** `|cos Δφ| ≤ 1`. Нарушение означает, что данные не
   описываются схемой «один вращающийся WGP × скаляр». На полосе 0.2–2.0 ТГц нарушений
   **3 из 122**; выше 2 ТГц их доля растёт — там сигнал уже на уровне шума.
3. **Гармоники ≥6.** У `|E|²` их быть не может, поэтому их доля в невязке — тест на
   выход за модель. Считается **в метрике весов фита** и по базису, ортогонализованному
   к базису порядка 4; рядом печатается уровень, ожидаемый по чистой случайности, — без
   него доля не читается. На `test_grid_33_11` выходит **6.1 % при случайных 8.7 %**,
   то есть выхода за модель нет.

   Метрика здесь принципиальна, и это проверено ошибкой: невзвешенный счёт на тех же
   данных даёт **24.2 %**, потому что доля считается там, где невязка не минимизировалась,
   и яркая зона с большой абсолютной невязкой накачивает число. Разница между
   «есть выход за модель» и «нет» — целиком в выборе метрики. Приёмка это стережёт.

### Обусловленность плана углов

Фит отказывается работать при менее чем **пяти различных углах** и помечает результат
ненадёжным при `cond(XᵀX) > 50`. Это не перестраховка: в начале прогона углов мало, и
подгонка выдала бы уверенные числа из ничего.

| Набор углов | `cond(XᵀX)` |
|---|---|
| полный (`−100…100`, 51 точка) | **8.69** |
| обрезанный до `0…90` (22 точки) | **398.9** |

Предсказанная `σ(θ₀)` при обрезке хуже в **8.7 раза** — и это чистая геометрия плана,
до всякого шума.

## 7. Гауссово окно

Ширина задаётся как **FWHM в пс** — так и подписано в интерфейсе, потому что ширину
гаусса задают по-разному (σ, FWHM, 1/e) и без указания её читают наугад. Внутри
`σ = FWHM / (2√(2 ln 2))`.

Назначение двойное: отсечь эхо от переотражений и подавить шумовую дорожку от линий
поглощения воды. Ширина 1000 пс — фактическое выключение (проверено: спектр не меняется
ни на единицу младшего разряда), отдельный флажок тоже есть.

Форма окна для образца и референса одинакова. Центр — собственный пик каждой трассы
(по умолчанию) либо общий по пику референса. Режим центрирования виден в панели данных:
смещение окна относительно данных меняет не только фазу, но и модуль спектра.

## 8. Положение пика

Максимум `|E(t)|` с параболической интерполяцией по трём точкам — без неё разрешение
ограничено шагом сетки 0.104 пс, и сдвиг образца в доли шага не разглядеть.

**Постоянная составляющая вычитается перед поиском пика всегда**, независимо от режима DC
для `T`. Причина измерена: у `011_a90.txt` максимум сырого `|E|` садится на случайную
точку базовой линии и даёт 14.062 пс вместо 14.539 пс — промах почти на пять шагов сетки.

## 9. Выбор референса

| Режим | Правило |
|---|---|
| **ближайший ранний** (по умолчанию) | `NNN_bg.txt` с наибольшим номером меньше номера трассы |
| ближайший поздний | с наименьшим номером больше номера трассы |
| среднее двух | оба соседних |

«Ближайший ранний» — по умолчанию не произвольно: именно этим правилом пользовалось ядро.
`test_grid_33_11_0deg_rep1_bg.txt` побайтно равен `002_bg.txt`, `_90deg_rep1_bg` —
`010_bg.txt`, `_0deg_rep2_bg` — `066_bg.txt`.

Усреднение двух референсов:

* **во времени** — усредняются два **интеграла**, а не трассы: расхождение задержек между
  референсами дало бы интерференционное занижение;
* **в спектре** — усредняются два `|FFT|²`, то есть **по мощности** (решение владельца
  O-3). Комплексное усреднение отвергнуто по измерению: на паре `002_bg`/`006_bg` оно
  завышает `T` **в 8.6 раза на 2.76 ТГц**, где отношение сигнал/шум уже мертво —
  деструктивная интерференция двух шумовых спектров в знаменателе. В рабочей полосе
  разница между способами 0.15 %.

В режиме усреднения панель показывает расхождение референсов (отношение энергий, разность
пиков) и предупреждает, если оно превысило 5 %.

**Край прогона.** У первой трассы нет раннего референса, у последней — позднего. Откат на
единственный доступный делается, но **всегда с явной пометкой**: молча подменять референс
нельзя, иначе точка на границе прогона выглядит как обычная.

## 10. Совместимость с целевой машиной

Разработка — Python 3.14 / numpy 2.5 / matplotlib 3.11. Целевая машина — Windows 7 /
Python 3.8 / numpy 1.21.6 / matplotlib 3.5.3 (последние версии, работающие на этой ОС).

`np.trapz` **удалён** в numpy 2, `np.trapezoid` **отсутствует** в 1.21 ⇒ ни то, ни другое
использовать нельзя. В `core/compat.py` собственная трапеция: один и тот же код и
одинаковые числа на обеих машинах.

Синтаксис проверяется `tools/check_py38.py` (`ast.parse(feature_version=(3,8))`).
Он ловит синтаксис, но **не семантику библиотек** — за неё отвечают `compat.py` и прогон
приёмки на самой машине у прибора.
