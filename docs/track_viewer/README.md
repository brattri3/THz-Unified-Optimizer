# track_viewer — контроль углового прогона THz-TDS

Инструмент оператора у спектрометра: показывает угловую зависимость пропускания
**прямо во время съёмки** и раскладывает «дорогу» пустых файлов под следующий прогон.

**Зона C.** ТЗ — `docs/artifacts/C_TZ_tds_track_viewer.md`, согласовано с владельцем
2026-08-12. Открытые вопросы O-1…O-7 из §8 ТЗ закрыты владельцем в тот же день; решения
перечислены ниже и в `coordination/ACTIVITY.md`.

## Зачем

Качество прогона сейчас видно только постфактум, после обработки в `unified_optimizer`.
Съехавший образец, перепутанные `sig`/`bg` или испорченная трасса обнаруживаются через
часы или дни, когда прогон уже не переснять. Прецедент задокументирован: `test_grid_40_20`
дал `T = 105.7 %` из-за перепутанных файлов, и это едва не ушло в отчёт.

Это **контроль съёмки, а не анализ**. Модель не подгоняется, `unified_optimizer` не
импортируется вовсе. Физика остаётся в ядре.

## Запуск

```powershell
# из корня репозитория
.venv\Scripts\python.exe -m track_viewer.gui                       # окно
.venv\Scripts\python.exe -m track_viewer.gui data_pool\test_grid_33_11
.venv\Scripts\python.exe -m track_viewer.cli data_pool\purewave    # консоль
.venv\Scripts\python.exe -m track_viewer.cli <каталог> --csv трек.csv
.venv\Scripts\python.exe -m track_viewer.selftest                  # приёмка, 19 проверок
```

Инструменты разработчика (в поставку не входят):

```powershell
.venv\Scripts\python.exe track_viewer\tools\check_py38.py       # совместимость с 3.8
.venv\Scripts\python.exe track_viewer\tools\smoke_gui.py        # прогон интерфейса
.venv\Scripts\python.exe track_viewer\tools\make_win7_kit.py    # сборка комплекта Win7
```

## Устройство

| Файл | Что внутри |
|---|---|
| `core/compat.py` | своя трапеция: `np.trapz` удалён в numpy 2, `np.trapezoid` отсутствует в 1.21 |
| `core/scan.py` | каталог прогона → список трасс; отбор по журнальной нумерации, кэш |
| `core/physics.py` | `T` во времени и по частоте, окно, пик, выбор референса |
| `core/road.py` | генератор дороги пустых файлов и гардрейлы §5.2 |
| `gui.py` | Tkinter + matplotlib: 4 панели, слайдер, панель данных, окно генерации |
| `cli.py` | то же ядро без окна: печать трека, выгрузка CSV |
| `selftest.py` | приёмка §7 ТЗ, 19 проверок |

**Инвариант: в `core/` нет ни `tkinter`, ни `matplotlib`.** Благодаря этому вся приёмка
проходит без графического окружения. Проверяется машинно, тестом, а не договорённостью.

## Проверка

`python -m track_viewer.selftest` — 19 проверок, из них главная сверяет число с ядром:

```
без DC          T = 98.9089 %  ← число ТЗ §7.2
предымпульс 15% T = 99.4231 %  ← режим по умолчанию
расхождение по трактовке DC: +0.514 п.п.
```

Разбор расхождений и обоснование трактовки DC — `01_FORMATS.md`.

## Что инструмент не делает

* не подгоняет модель и не обращается к `unified_optimizer`;
* не изменяет и не удаляет измеренные трассы ни при каких настройках;
* пишет в каталог данных только пустые файлы, `META.txt` и `README.md`, и только при
  явной генерации дороги;
* не обновляется по таймеру — чтение каталога в момент записи трассы прибором вернуло бы
  обрезанный файл;
* не заменяет `MEASUREMENT_ORDER.md` и предполётный чек-лист: центровка образца
  проверяется руками, инструмент этого не видит.
