# coordination/tools/ — инструменты координации

**Заведён заново 2026-08-23** сессией `orch-cloud`. Каталог с таким именем уже существовал и был
**удалён намеренно**, поэтому граница фиксируется письменно — иначе через месяц никто не отличит
новый инструмент от воскресшего отменённого.

## Что было отменено и не подлежит восстановлению

Решение владельца **В-27 от 2026-08-15** отменило целиком слой координации сессий как процессов:
механизм `.lock`, таймаут 15 минут, коды возврата, процедуру `[STALE-LOCK]`, heartbeat, реестр
ников. Вместе с ним в `archive/coordination-locks-2026-08/tools/` перенесены четыре скрипта:

| Файл | Почему не возвращается |
|---|---|
| `preflight.py` | занимал `.lock`, на который больше никто не смотрит. Код работоспособен — в этом и опасность |
| `stress_test_lock.py` | тест отменённого механизма |
| `kpi_stats.py` | читал `NICKS.md` (реестр закрыт 07.08) и `~/.claude/projects/**/*.jsonl` (привязка к машине, субагентов не видит) |
| `kpi_report.py` | рендерер для `kpi_stats.py` |

Действующее правило: **кто сейчас работает — `claude agents`**, а не файл. Любой новый инструмент,
отвечающий на этот вопрос, заведомо лишний. Это отдельная обязанность ORCH — следить, чтобы
отменённое не отрастало (`ORCHESTRATOR.md`).

## Что лежит здесь сейчас

### `kpi_git.py` — выработка ролей по git

**Не воскрешение `kpi_stats.py`.** Тот измерял процессы (чаты, ники, токены, локи) из локальных
транскриптов; этот измеряет **предметную выработку** из единственного источника, доступного во
всех трёх контурах, — истории git. Он ничего не знает о сессиях, ников не читает, `.lock` не
создаёт и на вопрос «кто сейчас работает» не отвечает.

```
python coordination/tools/kpi_git.py                                  # сводка в терминал
python coordination/tools/kpi_git.py --json coordination/reports/kpi_git.json
```

Две поправки, без которых цифры врут (обе зашиты в скрипт, разбор —
`reports/GIT_HISTORY_2026-08-23.md`):

1. **Считает по `--all`, а не по `main`.** У репозитория два корня без общего предка; на `main`
   не существует ролей B, D, L, P.
2. **Исключает оба корневых коммита** — это импорты рабочего дерева (`a1f69c2`: 1243 файла,
   618 872 строки под тегом `[C]`; `91fc814`: 250 файлов, 179 236 строк), а не работа роли.

И одна методическая: **строки делятся на «работу» и «данные»** (`data_pool/`, `archive/`,
`research/results/`). Без этого деления метрика завышала вклад роли A в пятнадцать раз — из её
311 876 добавленных строк 291 548 составляли спектры измерений и машинный вывод прогонов, а
авторской работы было 20 328.

**Чего инструмент не даёт: стоимости и токенов.** В git их нет. Стоимость по ролям даёт только
телеметрия (`CLAUDE_CODE_ENABLE_TELEMETRY=1` + OTLP-коллектор; метрики `claude_code.cost.usage` и
`claude_code.token.usage` с атрибутами `agent.name`, `query_source`, `model`, `effort`) — владелец
решил 2026-08-23 её пока не поднимать. Разовый срез расхода — команды `/usage` и `/insights`.

## Правило для будущих инструментов здесь

Инструмент уместен, если отвечает на вопрос **о предметной работе** (что сделано, кем, когда,
какой ценой) и берёт данные из того, что переживает машину: git, файлы репозитория, телеметрия.
Инструмент, отвечающий на вопрос **о процессах** (кто запущен, кто держит роль, кто жив), —
дублирует CLI и заводиться не должен.
