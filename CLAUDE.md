# CLAUDE.md — THz-Unified-Optimizer

Гид для агентов по этому репозиторию. Язык документации и коммитов — русский.

## Что это

Извлечение физических параметров проволочных поляризаторов (WGP: период `P`, эффективный
диаметр проволоки `D_eff`) из данных THz-TDS. Ядро — аналитическая модель **Бланко 1986**
(эквивалентные схемы → `t_perp`, `t_par`) в формализме матриц Джонса, поверх неё —
поправки (Друде, степенное рассеяние `ν^γ`, фазовые задержки, утечка параллельного канала).

Репозиторий состоит из **двух почти независимых слоёв**:

| Слой | Каталог | Состояние |
|---|---|---|
| Продакшн-пайплайн | `unified_optimizer/`, `scripts/`, `docs/` | заморожен, содержит 2 сломанные функции (см. ниже) |
| Исследовательский слой | `research/` | активный; всё новое пишется сюда |

Активная работа идёт в `research/`. Продакшн-пакет используется исследованием **только
как библиотека** (`model_blanco`, `config`, `data_manager`, две функции из `optimizer_2d`).

## Команды

```powershell
# окружение (Windows, venv уже создан)
.venv\Scripts\python.exe -m pip install -r requirements.txt

# продакшн-пайплайн (ВНИМАНИЕ: 2D-ветка падает, см. «Известные дефекты»)
.venv\Scripts\python.exe -m unified_optimizer.run_pipeline --method 1d
# --dataset series1 | --method 1d|2d|both | --no-global
# отчёт -> results/optimization_report.md

# тесты продакшн-пакета
.venv\Scripts\python.exe -m pytest unified_optimizer/tests -q

# исследовательские скрипты — ВСЕГДА из корня репозитория
.venv\Scripts\python.exe research/experiments/t1_baseline.py
.venv\Scripts\python.exe research/experiments/t20_weighted_fit.py --dataset specac --dphys 14.0 --nboot 40
.venv\Scripts\python.exe research/two_wgp/model_2wgp.py --selftest
.venv\Scripts\python.exe research/experiments/verify_model_core.py   # бит-в-бит сверка рефакторинга
```

Скрипты в `research/` сами вставляют корень репозитория в `sys.path`
(`REPO = Path(__file__).resolve().parents[2]`) — запуск из другого CWD ломает пути к данным.

## Известные дефекты продакшн-кода (проверено запуском)

1. `unified_optimizer/optimizer_2d.py:122` — `d_max_um = p_max_um - 0.5`, имя `p_max_um`
   **нигде не определено** → `optimize_2d_spectral()` падает с `NameError` при любом вызове.
   Значит `run_pipeline --method 2d|both` (дефолт — `both`) нерабочий.
2. `unified_optimizer/optimizer_lmfit.py:92` — вызов `model_blanco.estimate_deff_initial(...)`
   при отсутствующем `import model_blanco` → `run_lmfit_2d()` тоже `NameError`.

Модуль-уровневые функции `optimizer_2d.get_transmission_spectra` и
`compute_theoretical_grid_2d` работают нормально — именно их импортирует `research/`,
поэтому исследовательский слой не задет. **Не «чинить между делом»**: любая правка
`unified_optimizer/` меняет базовую линию всех фитов Фаз 1–3; сначала спросить владельца.

## Модель: что важно знать до правок

- `model_blanco.py` — скалярные `compute_t_perp` / `compute_t_par` (частотно-зависимые,
  Друде включается через `freq_thz`). `transmission_two_polarizers` / `..._complex_...`
  предполагают **два идентичных** WGP и не зависят от частоты.
- `optimizer_2d.compute_theoretical_grid_2d:68` строит
  `E_out = cos²θ·t_perp_eff + sin²θ·t_par_eff` — это «один реальный WGP + **идеальный**
  анализатор». Реальная установка — два реальных WGP.
- `research/experiments/model_core.py` — векторизованное кэширующее ядро, **бит-в-бит**
  эквивалентное скалярному оригиналу (`verify_model_core.py` это проверяет). Есть
  специальные хелперы `_cmul` / `_cpython_cdiv`, воспроизводящие ULP-поведение скалярного
  numpy/CPython. Не «упрощать» их — сломается бит-сверка.
- `research/two_wgp/model_2wgp.py` — корректная двух-WGP модель Джонса с per-element
  геометрией. Конвенция: **угол = ориентация оси ПРОПУСКАНИЯ** (⊥ проводам), провода = угол+90.

## Ключевые научные результаты (не переоткрывать)

Полностью — в `research/SYNTHESIS.md`. Сжато:

- Текущая опорная модель **M5** = Бланко + Друде + рассеяние `ν^γ` + `D_eff`, приколоченный к
  ЭФФЕКТИВНОМУ значению + явная утечка `η(ν)·e^{j(δ0+2πν·τ_leak)}`.
- **Загадка `D_eff`**: фит требует `D_eff/D_phys ≈ 0.43–0.64` на 3 образцах; пин к
  физическому диаметру катастрофичен (`dAIC +6000…+9000`). Точный lattice-sum эталон даёт
  `D_eff/D_phys ≈ 1` ⇒ закон **не геометричен**, `D_eff` — прокси недостающей физики. Открыто.
- **Утечка `t_par` универсальна** (6 образцов, `η ≈ 0.012–0.036`), тройное подтверждение
  HN2/HN7/HN8; `τ_leak ≈ 0.19 пс`.
- `D_eff ↔ η` **полностью вырождены** (корреляция ±1.0) — свободный фит обоих бессмыслен.
- **Теорема выравнивания (A1/T8, доказана)**: если ось пропускания WGP2 совпадает с осью
  детектора, реальный WGP2 тождественно равен идеальному анализатору × скаляр `t_perp2(ν)`.
  ⇒ гипотеза «загадка D_eff = отсутствующий WGP2» **опровергнута** аналитически и на данных
  (A2: `dAIC = +0.15`, `D_eff` не изменился в 4 значащих цифрах).
- Отвергнуто: HN3 (Фабри-Перо), HN4 (нерегулярность), HN9 (линия 0.215 ТГц = артефакт края
  полосы), HN10 (апподизация), HN11 (общий γ), рассогласование `φ2` как замена `ε_cross`.
- **Методическое**: угловые добавочные параметры здесь мультимодальны. Всегда мультистарт
  (тёплый старт из подмодели + альтернативный бассейн) — холодный старт завышает значимость.

## Данные

`data_pool/{dataset}_{angle}deg_rep{N}_{sig|bg}.txt` — две колонки (время, поле).
`DataManager` рекурсивно сканирует `data_pool/`, поэтому подкаталоги (`purewave/`, `specac/`)
подхватываются как отдельные датасеты автоматически. Пустые файлы-заглушки пропускаются.

Геометрия образцов (микрофото ground truth) — `research/experiments/fit_lib.py:GEOMETRY`.
`series1..5` — геометрия НЕизвестна, полный M5-фит для них заблокирован.
