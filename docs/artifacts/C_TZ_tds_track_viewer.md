# ТЗ — `tds_track_viewer`: интерактивный контроль углового прогона THz-TDS

**Зона:** C (`c-app`) · **Заказчик:** владелец · **Составил:** ORCH, 2026-08-12
**Статус:** согласовано в части требований; стек и размещение кода — решение сессии C.

---

## 1. Зачем

Сейчас качество углового прогона видно только постфактум, после обработки в
`unified_optimizer`. Ошибку установки, съехавший образец или испорченную трассу
обнаруживают через часы или дни. Инструмент нужен, чтобы **видеть угловую
зависимость прямо во время съёмки** и останавливать прогон, когда он пошёл не так.

Работает на ПК спектрометра под **Windows 7**, офлайн, без доступа к репозиторию.
Все расчёты — динамические, никаких предвычисленных таблиц.

## 2. Формат входных данных (установлен по `data_pool/purewave`, `data_pool/test_grid_33_11`)

### 2.1 Именование

Каталог одного прогона, сквозная нумерация с ведущими нулями:

| Шаблон | Что это | Как трактовать |
|---|---|---|
| `NNN_a<угол>.txt` | трасса образца, угол в градусах со знаком (`003_a0.txt`, `047_a-94.txt`) | точка на угловой зависимости |
| `NNN_bg.txt` | референс (открытый пучок) | знаменатель пропускания |
| `NNN_META.txt` | метаданные, **не трасса** | исключить из нумерации |
| прочее (`README.md`, `MEASUREMENT_ORDER.md`, `*.md`) | сопровождение | игнорировать молча |

Регулярное выражение отбора трасс: `^(\d{3})_(a(-?\d+)|bg)\.txt$`.
**Всё, что не совпало, — не трасса.** Это и есть автоматический отсев мета-информации.

**Изменение по требованию владельца:** в новых прогонах `META` выводится из сквозной
нумерации. Вместо `001_META.txt`, `018_META.txt`, `034_META.txt` создаётся
**единственный `META.txt`** (без номера) в корне каталога прогона, заполняемый один раз
в начале эксперимента. Формат содержимого — как `000_META_TEMPLATE.txt` из
`test_grid_33_11`. Старую схему `NNN_META.txt` парсер обязан продолжать понимать
и пропускать: архивные каталоги должны открываться.

### 2.2 Содержимое файла трассы

Текст, три колонки, разделитель — табуляция, шапки нет:

```
0.000000	-0.094188	570000.000000
0.104167	-0.094404	570200.000000
```

1. время задержки, **пс** (шаг ≈ 0.104167 пс);
2. амплитуда поля, отн. ед.;
3. позиция линии задержки — **назначение уточнить у владельца, в расчётах не участвует** (O-5).

Типичная трасса: 651 точка, окно ≈ 67.8 пс. Ни то, ни другое **не зашивать** —
читать из файла.

### 2.3 Пустой файл = «ещё не измерено»

Файл нулевого размера — законное состояние: дорога раскладывается заранее, пустышки
заполняются по ходу съёмки. Пустые файлы **пропускаются молча**, недоснятая дорога
обрабатывается штатно. Так же ведёт себя `DataManager` в ядре.

Файл ненулевого размера, который не удалось разобрать, — это **ошибка**: показать в
панели данных, точку на график не ставить, прогон не прерывать.

## 3. Расчёты

### 3.1 Пропускание во временной области (главная величина)

```
T = ∫ (E_s(t) − DC_s)² dt  /  ∫ (E_r(t) − DC_r)² dt
```

Интеграл — трапециями по всей трассе (по Парсевалю равен интегралу по спектру, поэтому
выбирать полосу усреднения не требуется — в этом весь смысл величины).

**DC-составляющая** по умолчанию — среднее по **предымпульсному участку** (первые 15 %
отсчётов), а не по всей трассе: хвост осцилляций смещает полное среднее и вносит
систематику в интеграл. Метод и доля участка — в настройках.

Вывод: в долях (шкала 0…1) и в дБ, `10·lg T`.

### 3.2 Спектральное пропускание

FFT обеих трасс (после окна, если включено), затем

```
T(ν) = |FFT(E_s)|² / |FFT(E_r)|²
```

Полоса отображения по умолчанию 0.2…3.0 ТГц, настраиваемо. Точки, где спектр референса
ниже порога динамического диапазона, не отображать.

### 3.3 Гауссово окно

Опция «наложить окно», при включении — поле **ширины в пс** (интерпретировать как FWHM,
подписать это в интерфейсе явно). Назначение по словам владельца двойное: отсечь эхо от
переотражений **и** подавить шумовую дорожку от линий поглощения воды. Ширина 1000 пс —
де-факто выключение, отдельная кнопка отключения тоже нужна.

Окно применяется к образцу и референсу **одинаково по форме**. Центрирование — O-4:
по умолчанию каждая трасса центрируется на собственный пик; опция «общий центр по пику
референса». Учесть: смещение окна относительно данных меняет не только фазу, но и модуль
спектра, поэтому режим центрирования обязан быть виден в панели данных.

### 3.4 Положение пика

Максимум `|E(t)|` с **параболической интерполяцией по трём точкам** — иначе разрешение
по задержке ограничено шагом 0.104 пс, и сдвиг образца не разглядеть.

### 3.5 Выбор референса

Настройка с тремя режимами:

| Режим | Правило |
|---|---|
| **Ближайший ранний** | `NNN_bg.txt` с наибольшим номером, меньшим номера трассы |
| **Ближайший поздний** | `NNN_bg.txt` с наименьшим номером, большим номера трассы |
| **Среднее двух ближайших** | оба соседних референса |

Для режима усреднения:

* **во временной области** — посчитать интеграл квадрата для каждого референса
  отдельно и усреднить арифметически (не усреднять сами трассы: расхождение задержек
  между референсами даст интерференционное занижение);
* **в спектральной области** — наложить окно, взять FFT каждого референса, усреднить
  поточечно. Комплексное усреднение или усреднение модулей — **O-3**, требует решения;
  по умолчанию комплексное, но в панели данных показывать расхождение двух референсов,
  чтобы владелец видел, когда усреднение неуместно.

В режиме усреднения панель данных показывает характеристики **обоих** референсов.

Краевой случай: у первой трассы нет раннего референса, у последней — позднего.
Откатываться на единственный доступный и **помечать это в панели**, не молча.

### 4.1 Графики

**Четыре панели, попарно.** Верхняя пара — главная, угловая зависимость; нижняя —
спектральная для выбранного измерения. В каждой паре: слева линейная шкала `0…1`,
справа та же величина в дБ.

Требования:

* **Никаких двойных осей Y.** Линейная и логарифмическая — это две отдельные панели,
  а не две шкалы на одном поле.
* Оси угловых графиков фиксированы `0…1` по требованию владельца. Точка с `T > 1`
  (шум, сбой референса, ошибка сопоставления файлов) **не обрезается молча**: она
  прижимается к границе и красится в предупреждающий цвет, а в панели данных
  появляется явное сообщение. Прецедент есть: `test_grid_40_20` давал `T = 105.7 %`
  из-за перепутанных `sig`/`bg`, и это едва не ушло в отчёт.
* Точка, выбранная слайдером, подсвечена на **обеих** угловых панелях.
* Повторные измерения того же угла (`rep2` в существующих прогонах — один угол снят
  дважды в разное время) должны быть различимы: разный маркер или оттенок, не наложение
  двух точек в одно место. Это прямая мера дрейфа, терять её нельзя (O-7).
* Идентичность серий кодируется не только цветом (форма маркера), легенда обязательна.

### 4.2 Слайдер

Перебирает **только непустые сигнальные трассы** в порядке сквозного номера; референсы
и мета пропускаются. Движение слайдера меняет обе нижние панели и подсветку на верхних.
Кроме слайдера — стрелки `←`/`→` и поле ввода номера.

### 4.3 Панель данных (под графиками)

Имя файла · порядковый номер · угол · имя референса (или обоих) · положение пика
образца и референса(ов) в пс и их разность · `∫E²` образца и референса · `T` в % и дБ ·
активный режим окна, центрирования и DC · предупреждения.

### 4.4 Кнопка «Обновить»

Перечитывает каталог: новые непустые файлы добавляются на график, ранее прочитанные
берутся из кэша по паре (`размер`, `mtime`). Полный пересчёт — отдельной кнопкой.
Автообновление по таймеру **не делать** без отдельной просьбы: чтение каталога во время
записи трассы прибором может дать обрезанный файл.

### 4.5 Экспорт

Кнопка сохранения текущего угового трека в CSV (`номер, файл, угол, референс, ∫E²_s,
∫E²_r, T, T_дБ, пик_s, пик_r`) — для дальнейшей вёрстки в Origin Pro. Origin-скрипт
как таковой **не разрабатывается**: динамический слайдер в Origin 2018 делается только
через Origin C с диалогом, это дороже Python и хуже сопровождается.

## 5. Генерация трека пустых файлов

Обобщение существующего `research/two_wgp/prepare_road_test_grid_33_11.py` — там уже
реализованы нужные гардрейлы, переписывать с нуля не надо.

### 5.1 Настройки

* **имя образца** (для `README.md` и шапки `META.txt`);
* **основной диапазон**: от, до, равномерный шаг;
* **второй диапазон** (опционально): от, до, уменьшенный шаг — уточняющий обход зоны
  гашения;
* **частота референса**: `один в начале` · `в начале и в конце` · `в начале, каждые n и
  в конце`. По умолчанию — третий вариант с **n = 3**, как в `purewave` и
  `test_grid_33_11`;
* **число повторов** каждого угла (по умолчанию 1);
* порядок обхода углов — O-6.

Создаётся один `META.txt` по шаблону (см. §2.1) и `README.md` с планом.

### 5.2 Защита от перезаписи — обязательна и жёстка

1. Создаются **только файлы нулевого размера**.
2. Существующий файл **не перезаписывается никогда** — ни пустой, ни заполненный.
3. Если в каталоге найден **непустой** файл с конфликтующим именем — операция
   отменяется целиком, ни один файл не создаётся, показывается список конфликтов.
4. Сначала **предпросмотр** (что будет создано, что уже есть, что мешает), создание —
   только вторым явным нажатием.
5. Удаление и усечение файлов инструмент не выполняет **ни при каких настройках**.

Пункты 2–3 не подлежат смягчению: цена ошибки — затёртые измерения, которые нельзя
восстановить.

## 7. Приёмка

Инструмент считается готовым, когда:

1. Открывает `data_pool/test_grid_33_11` и `data_pool/purewave` из архива и строит
   угловую зависимость, не спотыкаясь о `NNN_META.txt`, `README.md`,
   `MEASUREMENT_ORDER.md` и нормализованные файлы `*_sig.txt` / `*_bg.txt`, лежащие в
   тех же каталогах.
2. Значение `T` для яркого положения `test_grid_33_11` сходится с
   `research/results/a18_microscopy/a21_transmission.json` (**98.9 %**) в пределах
   различий в трактовке DC — расхождение объяснено, а не списано.
3. Слайдер проходит весь трек без исключений; спектральные панели меняются.
4. Генератор на каталоге с уже снятыми данными **отказывается** работать и перечисляет
   конфликты.
5. Запускается на Windows 7 с чистой машины без установки Python.

Пункт 2 — главный: инструмент, расходящийся с ядром без объяснения, вреднее отсутствия
инструмента.

## 9. Что инструмент делать НЕ должен

> **Пересмотрено владельцем 2026-08-13.** Первый пункт ниже стоял в редакции «не
> подгоняет модель и не обращается к `unified_optimizer`». Запрет на подгонку **снят**:
> владелец заказал раздел фитирования, оговорив линеаризованный подход ради работы на
> старом ПК. Запрет на обращение к `unified_optimizer` остаётся в силе. Реализация —
> `track_viewer/core/fit_malus.py`, обоснование и числа — `docs/track_viewer/01_FORMATS.md` §6.3.
>
> Существенная граница, которую замена запрета НЕ отменяет: инструмент подбирает только
> то, что угловой скан способен определить, — пропускание двух каналов, утечку, угол
> столика. Геометрия (`P`, `D_eff`) и материальные параметры не извлекаются здесь **и не
> могут быть извлечены в принципе**: угловая развёртка на одной частоте ограничивает не
> более пяти вещественных чисел. Физика сверх этих пяти остаётся в ядре.
>
> Метод принадлежит зоне A (`A0_malus_linearization`) и в зону C только **скопирован**;
> строка о согласовании трактовки — в `coordination/QUESTIONS.md`.

* Не обращается к `unified_optimizer` — числа с ним сверяются, но не берутся у него.
* Не пишет в каталог с данными ничего, кроме пустых файлов трека, `META.txt` и
  `README.md` при явной генерации.
* Не изменяет и не удаляет измеренные трассы.
* Не заменяет `MEASUREMENT_ORDER.md` и предполётный чек-лист: центровка образца
  проверяется руками, инструмент этого не видит.
